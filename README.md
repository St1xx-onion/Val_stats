# Valorant Stats

Фоновая консольная утилита: сидит и ждёт, пока начнётся матч, и с agent select
держит на экране одну живую таблицу по всем игрокам —
ранг, RR, пиковый ранг, счёт за акт, винрейт, рейтинг формы, ACS, KAST, HS%,
K/D, damage delta, нож и сколько раз вы с этим человеком уже пересекались.
Когда матч заканчивается — печатает его итоговый счёт и результат каждого.

Идея и набор эндпоинтов взяты из открытых проектов
[vRY](https://github.com/zayKenyon/VALORANT-rank-yoinker),
[ValoTrack](https://github.com/kurtxtb/ValoTrack) и
[ValoTracker](https://github.com/Londopy/ValoTracker); код здесь свой и заметно
компактнее.

## Как запустить

Нужен Python 3.10+ (проверено на 3.14).

Просто двойной клик по `run.bat`. Первый запуск сам найдёт Python, создаст
`.venv`, поставит зависимости и сделает `config.json` — примерно минута.

```
run.bat               — рабочий режим, ждёт матч
run.bat test          — самопроверка: контент, lockfile, токены, регион, ваш ранг
run.bat check         — офлайн-тесты разбора, без игры и без сети
run.bat reset         — стереть локальную память матчей и кэш справочников

run.bat who <ник>     — что база помнит об игроке: форма и ранг на момент встреч
run.bat top [n]       — с кем вы чаще всего пересекаетесь
run.bat backfill [n]  — прогреть кэш своей историей, чтобы первое лобби было дешёвым
run.bat calibration   — по чему сейчас считается счёт 0-1000
```

Первые четыре команды и `who` / `top` / `calibration` работают без игры;
из них в сеть ходит только `backfill`, и только за вашей собственной историей.

Окно не закрывается после выхода, так что ошибку видно и при двойном клике.
Если Python не в PATH — скажет об этом прямо, а не мигнёт консолью.

Вручную, без `.bat`:

```
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\python -m valstats.selftest
.venv\Scripts\python -m valstats
```

Порядок: сначала запускаете Riot Client (логин), потом утилиту. Она сама
дождётся клиента, если запустить наоборот, и переподключится, если клиент
перезапустить.

## Что читаем и откуда

**Никакого чтения памяти игры, инжекта DLL, хуков и обхода Vanguard.** Только
HTTP:

| Источник | Что берём |
|---|---|
| `%LOCALAPPDATA%\Riot Games\Riot Client\Config\lockfile` | порт и пароль локального API |
| `https://127.0.0.1:<порт>/entitlements/v1/token` | access token, entitlement, свой PUUID |
| `https://127.0.0.1:<порт>/chat/v4/presences` | `sessionLoopState` — MENUS / PREGAME / INGAME |
| `%LOCALAPPDATA%\VALORANT\Saved\Logs\ShooterGame.log` | регион, шард и строка билда |
| `glz-.../pregame/v1/...`, `.../core-game/v1/...` | состав лобби, агенты, лоадауты |
| `pd.../name-service/v2/players`, `pd.../mmr/v1/players/...` | ники, ранг, RR, история по актам |
| `pd.../match-history/v1/history/...`, `pd.../match-details/v1/matches/...` | ACS, HS%, K/D за последние матчи |
| `valorant-api.com` | справочники агентов, рангов, актов, скинов (кэш на сутки) |

Опрашивается только локальный presence раз в секунду. У аккаунта их несколько
(свой presence публикует и сам Riot Client — без состояния сессии), поэтому
берётся именно presence VALORANT. Если игра запущена, а состояния в presence
нет, состояние доспрашивается у `pregame/core-game` — не чаще раза в 5 секунд.
Остальные запросы наружу уходят исключительно в момент смены состояния: ~12 на
само лобби, плюс подгрузка формы (см. ниже).

### Форма: Score, ACS, KAST, HS%, K/D, DD

Всё считается из `match-details`, взятого у Riot напрямую, а не с сайта
tracker.gg. `match-history` даёт id последних competitive-матчей игрока,
`match-details` — полный разбор по раундам:

| Колонка | Откуда |
|---|---|
| ACS | `stats.score` / `stats.roundsPlayed` |
| HS% | `roundResults[].playerStats[].damage[]` — `headshots`/`bodyshots`/`legshots` |
| K/D | `stats.kills` / `stats.deaths` |
| DD | (нанесённый урон − полученный) / раунды; урон берётся из тех же `damage[]` по полю `receiver` |
| KAST | раунды, где игрок сделал килл, ассист, выжил или был разменян (окно размена 3 с) |

**Score** — это аналог Tracker Score с tracker.gg. Их число проприетарное:
считается у них на сервере относительно всей популяции игроков, в API Riot его
нет, а Valorant отсутствует в публичном API самого tracker.gg. Поэтому здесь
свой рейтинг **по той же схеме** — те же четыре входа (ACS, KAST, DD, Win%), по
250 баллов каждый, сумма 0–1000.

**С числом на их сайте он не совпадёт и не должен.** Он нужен, чтобы за секунду
отранжировать лобби между собой.

#### Популяция вместо угаданных опорных точек

Сначала счёт считается по фиксированным полосам из `perf.BANDS` — это просто
разумные догадки для платины. Но популяция копится сама: каждый разобранный матч
кладёт в `encounters.db` строки **всех десяти** игроков. Как только наберётся 60
человек хотя бы с 40 раундами каждый, счёт переключается на перцентиль внутри
этой популяции — то есть по той же схеме, что у tracker.gg, только популяция
здесь ваша собственная и потому куда более уместная: это ваш диапазон рангов, а
не весь мир.

`run.bat calibration` показывает, что происходит сейчас:

```
Score calibration  1750 player-lines cached, 76 players with at least 40 rounds
| Metric   | Fixed band 0 / 250 | Your population 25 / 50 / 75 |
| ACS      |          130 / 300 |              184 / 207 / 240 |
| KAST     |            45 / 85 |                 80 / 83 / 87 |
| DD/round |           -40 / 60 |                -21 / -5 / 20 |
| Win%     |            20 / 70 |                 24 / 40 / 60 |
```

Хорошо видно, зачем это нужно: угаданная полоса KAST 45–85 в реальном лобби почти
не работает — живые значения лежат в 80–87, и по фиксированной шкале все получали
бы почти полные 250. Переключение отключается через `"rating_calibration": "fixed"`.

#### Пять матчей — это мало, и таблица об этом говорит

Колонка **N** — сколько матчей стоит за цифрами. Пока их меньше трёх, вся правая
часть строки печатается приглушённо: у человека с одним матчем в истории винрейт
равен 0% или 100%, и это ничего не значит.

Плюс к этому маленькая выборка **подтягивается к середине**, а не принимается на
веру: значение смешивается с нейтральной точкой пропорционально объёму (40 раундов
и 6 матчей — вес нейтрали). Один удачный матч на 30 килов больше не даёт 1000 из
воздуха: та же статистика на 13 раундах даёт ~630, а на полусотне матчей — ~985.

Всё считается **взвешенно**, а не как среднее средних: суммируем score и раунды
по всем матчам и делим один раз. Матч на 25 раундов и матч на 13 не должны иметь
равный вес.

Кэш живёт в `encounters.db` навсегда: результаты матчей неизменны. Причём один
скачанный матч кладёт в базу строки **всех десяти** игроков, а не только того,
ради кого качали. Поэтому холодный старт стоит до ~60 запросов, а дальше цена
лобби быстро падает — на союзников из общих матчей уходит только по одному
запросу истории. `run.bat backfill` разбирает вашу собственную историю заранее,
чтобы первое живое лобби не платило за холодный старт.

Форма берётся из очереди `performance_queue` (по умолчанию competitive). У кого
там пусто — например, играет только анрейтед, — история подтягивается без
фильтра по очереди, иначе половина таблицы была бы из прочерков. Отключается
через `"performance_queue_fallback": false`.

### Сколько запросов уходит наружу

Ники, MMR и история матчей запоминаются на сессию (`player_cache_minutes`).
Это важно из-за перехода agent select → карта: без памяти пять союзников
опрашивались бы дважды подряд, порядка 15 лишних запросов на каждый матч.

Все исходящие запросы идут через один общий тормоз: минимум `request_gap` между
ними, а на ответ 429 — пауза, которую попросил сам Riot (`Retry-After`), после
чего запрос повторяется. Строка под таблицей показывает, сколько запросов реально
ушло — остальное пришло из локального кэша.

### Одна таблица на матч

За матч печатается **ровно одна** таблица. Она появляется сразу, как только
виден состав, и дальше обновляется на месте: сначала подставляются ники и ранги,
потом нож, потом форма (это дюжина запросов, поэтому она приходит последней).
Agent select и заход на карту делят один и тот же блок — при старте матча
таблица просто дорастает вражеской половиной, а не печатается заново. Под
таблицей идёт строка состояния (`ранги — 6/10 игроков`), она же в конце
показывает, сколько запросов ушло наружу. Форма отключается через
`"fetch_performance": false`.

### Итог матча

Когда матч заканчивается и клиент возвращается в меню, утилита делает **один**
запрос за только что сыгранным матчем — своим собственным — и печатает итоговую
таблицу: счёт по раундам, ACS, K/D/A, KAST, HS% и damage delta каждого, плюс
изменение вашего RR, если Riot уже успел его записать.

Это дёшево вдвойне: тот же ответ кладёт в кэш строки всех десяти игроков.
Отключается через `"post_match_summary": false`.

### Ширина окна

Столбцы не обрезаются. Утилита считает нужную ширину и, если окно уже, убирает
наименее полезные колонки целиком — в таком порядке: Knife, Lvl, W/G, Peak, DD,
KAST, N, Seen, HS%, WR, Score, RR. Что скрыто, написано подписью под таблицей.
Team, Agent, Player, Rank, ACS и K/D остаются всегда. Полный набор помещается
примерно в 170 колонок; растяните окно — колонки вернутся сами при следующей
перерисовке.

### Про скрытых игроков и `match-details`

Важная деталь, которую стоит знать: Incognito («streamer mode») действует только
на **живой** путь поиска — на ответ `name-service` для игроков текущего матча.
Запись завершённого матча он не трогает, и `match-details` содержит
`gameName`/`tagLine` у всех, включая скрытых. Именно поэтому сторонние сайты
показывают реальные Riot ID в опубликованных матчах.

`perf.extract()` **намеренно читает только `subject` и блоки статистики** и
никогда не касается полей с именами. Плюс скрытые игроки вообще исключены из
загрузки истории. Раскрывать их ники утилита не будет — это и самый прямой путь
к бану, и главное, ради чего Riot эту настройку сделал.

## Что специально сделано «мягко»

- **Streamer mode уважается.** Игрок с `Incognito`, либо тот, чьё имя name-service
  вернул пустым, показывается как `[hidden]`, и по нему не запрашивается ни MMR,
  ни история матчей. Это прямое требование политики Riot.
- **Скрытый значок ранга акта уважается.** Если у игрока стоит
  `IsActRankBadgeHidden`, в колонке Peak будет `hidden`.
- **Никакого оверлея поверх игры.** Обычное окно консоли. Оверлеи с подсказками
  в реальном времени — отдельный и куда более жёсткий пункт правил Riot.
- **Никакого автолока агента и вообще никаких действий в игре.** Утилита только
  читает; ни одного запроса, который что-то меняет.
- **Пауза 150 мс между запросами**, чтобы не ловить 429.

## Настройка

Скопируйте `config.example.json` в `config.json` и правьте:

```json
{
  "poll_interval": 1.0,               // как часто опрашивать локальный presence
  "show_skins": true,                 // колонка с ножом (нужен один лишний запрос)
  "show_peak_rank": true,             // false — вообще не показывать пиковый ранг
  "respect_streamer_mode": true,      // не трогать скрытых игроков
  "track_encounters": true,           // локальная база «сколько раз уже виделись»
  "fetch_performance": true,          // Score / ACS / KAST / HS% / K/D / DD
  "performance_matches": 5,           // по скольким последним матчам считать
  "performance_queue": "competitive", // откуда брать форму
  "performance_queue_fallback": true, // если там пусто — взять любые матчи
  "post_match_summary": true,         // итоговая таблица после матча
  "rating_calibration": "auto",       // "fixed" — не переходить на перцентили
  "player_cache_minutes": 20,         // сколько помнить ники / MMR / историю
  "request_gap": 0.15,                // минимальная пауза между запросами, сек
  "region": null,                     // eu / na / ap / kr — если автодетект не сработал
  "shard": null,                      // обычно совпадает с регионом
  "client_version": null              // на случай, если лог устарел
}
```

Опечатка в имени ключа не проходит молча: неизвестные ключи и неподходящие типы
называются вслух при запуске, а значение берётся из умолчаний.

`encounters.db` — обычный SQLite рядом со скриптом. Никуда не отправляется,
удаляется просто удалением файла.

## Риск бана — читайте

Это **не чит**: Vanguard такое не детектит, потому что детектить нечего —
процесс не касается игры. Но правила Riot про сторонние приложения нарушаются
всё равно, по другой причине: **утилита показывает информацию, которую клиент
специально скрывает** — ранги и статистику соперников до и во время матча.
Политика Riot требует, чтобы данные игрока показывались третьим лицам только
после его явного согласия через RSO.

Что известно по фактам:

- Есть подтверждённые репорты банов с формулировкой *«external program that
  reveals hidden information»* — например
  [issue #290 в vRY](https://github.com/zayKenyon/VALORANT-rank-yoinker/issues/290)
  (июнь 2026).
- Сам vRY выпустил финальный релиз и закрылся, организация на GitHub
  заархивирована в 2026 году.
- Recon Bolt получил от Riot cease and desist в июле 2023 и был закрыт.
- Массовых банвейвов именно за трекеры не было — заносят точечно, вручную.

Смягчения выше (streamer mode, отсутствие оверлея, только чтение) снижают риск,
но **не убирают его**. Если хотите нулевой риск — поставьте
`"respect_streamer_mode": true` и смотрите только свою статистику, либо
пользуйтесь официальным приложением tracker.gg через Overwolf.

Тестируйте на том аккаунте, который не жалко.

## Ограничения

- Определение групп (кто с кем в пати) не реализовано: Riot не отдаёт эти данные
  по чужим игрокам, а восстанавливать их по истории матчей — десятки лишних
  запросов на матч.
- В agent select в соревновательном режиме видна только своя команда — это
  ограничение самого API, а не утилиты. Полный состав появляется при заходе на
  карту.
- Только Windows: пути к lockfile и логам захардкожены под неё.

## Структура

```
valstats/client.py    lockfile, токены, регион, HTTP к local/pd/glz, пейсинг, память
valstats/content.py   справочники valorant-api.com + кэш на диске
valstats/config.py    умолчания и проверка config.json
valstats/stats.py     разбор pregame/coregame/MMR в строки таблицы
valstats/perf.py      форма из match-history + match-details, рейтинг, калибровка
valstats/db.py        SQLite: встречи, снимки ранга, разобранные матчи, популяция
valstats/render.py    живая таблица и итоговая таблица матча
valstats/app.py       главный цикл: presence -> состояние -> экран -> итог
valstats/history.py   команды who / top / backfill / calibration
valstats/selftest.py  диагностика цепочки без матча
tests/test_stats.py   офлайн-проверки
```

Не связано с Riot Games. Используйте на свой риск.
